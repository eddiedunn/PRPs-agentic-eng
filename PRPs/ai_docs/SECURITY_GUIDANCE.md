# SECURITY GUIDANCE

This document outlines the new security model and enterprise governance procedures for the Codex-based PRPs framework. It replaces all Claude Code-specific controls and provides actionable guidance for users and enterprise teams.

## Layer 1: The Execution Sandbox
- Every Codex task runs in an **ephemeral, isolated Linux container**.
- The container has **no outbound network access by default**, preventing data exfiltration.
- The agent has **no access to the host machine's filesystem** or processes; its world is limited to a temporary copy of the repository.
- **Conclusion:** This layer provides the fundamental guarantee of *containment*. The agent cannot break out of its sandbox.

## Layer 2: The PRP as a Security Mandate
- The PRP is a primary security tool, setting the agent's policy for each task.
- All new PRPs must include a **Security Acceptance Criteria** section.
    - *Example:* "The new endpoint must validate input schemas using Zod."
    - *Example:* "All user IDs in log outputs must be masked."
- PRPs must include explicit negative constraints.
    - *Example:* "You MUST NOT log raw user passwords under any circumstances."

## Layer 3: The Human Reviewer as the Critical Control
- The interactive workflow is a key security feature.
- **Mandate Plan Review:** Developers *must* critically review the execution plan proposed by Codex before approving it. This is the checkpoint to catch flawed logic, insecure library choices, or unintended consequences.
- **Mandate Code Review:** All code generated by the agent must undergo the same level of human scrutiny as code written by a junior developer. The agent is a powerful tool, but the human is the final gate for quality and security.

## Enterprise Governance Procedures

### Dependency Management
- Supply-chain security is managed via manifest files (e.g., `package.json`, `pyproject.toml`).
- Enterprise teams must add a validation step to PRPs that runs `npm audit` or an equivalent tool to check for vulnerable dependencies *before* implementation.

### Secret Management Policy
- The Codex agent cannot directly access external secret vaults.
- The platform (e.g., GitHub Actions or ChatGPT Enterprise) should inject secrets (like a private npm token) as environment variables into the container at runtime.

### Audit Trail
- The full conversation history in the ChatGPT interface serves as a complete and immutable audit log of every instruction given to the agent and every result it produced. This is a powerful tool for compliance and incident review.
